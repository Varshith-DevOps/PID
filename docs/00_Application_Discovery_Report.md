# 00. Application Discovery Report — NexusHR HRMS

## 1. Executive Summary

NexusHR is a comprehensive, production-grade Human Resource Management System (HRMS) designed specifically for the Indian business environment. The application handles end-to-end employee lifecycle management, including core HR operations, dynamic role-based permissions, recruitment pipelines (Applicant Tracking System), leave workflows, shifts/roster management, attendance regularization (including biometric device and mobile geolocation validation), expense claims, project timesheets, performance appraisals, statutory payroll compliance, and full-and-final settlements (F&F).

### Authentication & Authorization Methods
* **Authentication:** Stateless, token-based authentication using JSON Web Tokens (JWT). JWT tokens are generated by the backend (`jwt.sign`) and verified on subsequent requests using a bearer token or cookies.
* **MFA (Multi-Factor Authentication):** Built-in support for Multi-Factor Authentication, including secrets, recovery codes, and verification timestamps in the `User` model.
* **Authorization:** Role-Based Access Control (RBAC). In addition to role-gating (e.g., `SUPER_ADMIN`, `ADMIN`), the system provides dynamic, granular permission mappings on a per-user and per-module level (CRUD operations plus export actions) stored in the `permissions` table.

## 4. Key Source Files and Their Purpose

### Backend Core
* **[`backend/src/index.js`](file:///e:/HRMS_application/backend/src/index.js):** Backend server entry point. Configures Express, rate-limiting, cookie parser, and mounts all 28 API routes.
* **[`backend/prisma/schema.prisma`](file:///e:/HRMS_application/backend/prisma/schema.prisma):** Complete database schema defining 54 tables with relational integrity rules.
* **[`backend/src/rbac/rbacMiddleware.js`](file:///e:/HRMS_application/backend/src/rbac/rbacMiddleware.js):** Gating layer that dynamically reads user roles and verifies database-level permission overrides before permitting request routing.
* **[`backend/src/controllers/permissionController.js`](file:///e:/HRMS_application/backend/src/controllers/permissionController.js):** Defines the default permission matrices for all 12 roles across 21 functional modules and handles local permission overrides.

### Compliance & Calculations Services
* **[`backend/src/services/salaryService.js`](file:///e:/HRMS_application/backend/src/services/salaryService.js):** Calculates employee earnings and statutory deductions (EPF, ESI, Professional Tax, Labor Welfare Fund, Gratuity, LOP).
* **[`backend/src/services/tdsEngine.js`](file:///e:/HRMS_application/backend/src/services/tdsEngine.js):** Projects taxable income, processes Old vs. New tax regimes, applies Section 80C/80D deductions, and determines monthly TDS withholding.
* **[`backend/src/services/fnfService.js`](file:///e:/HRMS_application/backend/src/services/fnfService.js):** Handles exit settlement payouts, leave encashments, and notice period recovery calculations.
* **[`backend/src/services/ecrGenerator.js`](file:///e:/HRMS_application/backend/src/services/ecrGenerator.js):** Generates the EPFO Electronic Challan-cum-Return (ECR) text files for monthly EPF filing.
* **[`backend/src/services/esicReportGenerator.js`](file:///e:/HRMS_application/backend/src/services/esicReportGenerator.js):** Generates Excel-based spreadsheets containing employer/employee contribution summaries for monthly ESIC filings.
* **[`backend/src/services/form16Generator.js`](file:///e:/HRMS_application/backend/src/services/form16Generator.js):** Compiles tax projections and YTD payroll records into standard PDF-based Form 16 documents.

## 5. API and UI Route Structure Summary

### API Routes Structure (Base URL: `/api`)
The backend exposes a highly RESTful set of routes. Major controllers are structured as:
* `/api/auth` — Login, registration, password changes, and MFA activation.
* `/api/employees` — Employee master data management and address/education/experience/dependent sub-resources.
* `/api/attendance` — Shift assignments, web-punching, regularizations, and biometric integrations.
* `/api/leave` — Leave requests, balances, and approval routing.
* `/api/payroll` — Salary structures, payroll processing runs, and compliance actions.
* `/api/recruitment` — Job openings, applicant screening stages, panel interviews, and offer generation.
* `/api/expenses` — Expense claim submissions and travel advances.
* `/api/performance` — KRA setup, appraisal workflows, and 360-degree reviews.

### UI Routes Structure
The Next.js frontend is organized around page folders matching backend functionalities:
* `/` — Root page handling auth validation and redirection.
* `/dashboard` — Landing view containing analytics charts.
* `/employees` & `/employees/[id]` — Employee directories and profiles.
* `/attendance`, `/leave`, & `/payroll` — Core HR transactional screens.
* `/recruitment` — ATS candidate tracking and pipeline.
* `/org-chart` — Interactive reporting hierarchy view.
* `/shifts` & `/checklists` — Admin setups and onboarding processes.
* `/platform` — Tenant/company structure setup panel.
